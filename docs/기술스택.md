## 각 결정의 근거 (비개발자용 요약)

### 1. Chromium + Electron
브라우저 = 엔진 + 껍데기. Chromium은 구글의 무료 엔진으로 크롬·엣지·웨일이 다 이걸 씀. Electron은 이 엔진 위에 우리 껍데기를 올리는 조립 키트(VS Code·디스코드·노션이 사용). 대안 Tauri(엔진 제어 약함), CEF(C++ 직접), Chromium 소스 수정(개발자 수십 명), 크롬 확장앱(브라우저 자체 못 바꿈)은 모두 부적합.

### 2. AI 제공자 어댑터
```
브라우저 도구(MCP: 클릭·입력·이동·폰 문자·Vault 입력) ← 공용
        ▲
  AI 제공자 어댑터 (설정에서 선택, 작업별 지정 가능)
   ├─ Claude 구독  → Claude Agent SDK (Claude Code 로그인 재사용)  1순위
   ├─ ChatGPT 구독 → Codex CLI (설치됨)                             2순위
   ├─ API 키 (Claude / OpenAI / Gemini)                             3순위
   └─ 로컬 AI (Ollama)                                              추후
```
구독 제한·한도 발생 시 다른 제공자로 전환. 도구·Vault·폰 연동은 그대로.

### 3. React 묶음
React는 화면을 부품(컴포넌트)으로 조립. Tailwind는 꾸밈 규칙, shadcn/ui는 완성 부품(Button, Dialog, Tabs, Badge, Sheet, Table…), Zustand는 앱 공용 상태 메모장, React Hook Form+Zod는 입력 폼과 값 검사.

### 4. SQLite + Supabase
- 로컬 SQLite: 빠르고 오프라인. `%APPDATA%\samba-browser\data.db`, 일 1회 백업.
- Supabase: 이메일+비밀번호 로그인(구글 로그인 추후). 동기화 범위 = 채팅 기록·설정·계정 목록·Vault 암호문·레시피/절차·작업 로그. 폰 연결 정보는 PC별.
- 종속성: Supabase는 PostgreSQL 표준이라 데이터 이사 가능, 오픈소스라 자체 설치 가능. 동기화 코드는 어댑터로 분리해 PocketBase 등으로 교체 가능하게.
- 충돌 규칙: 마지막 수정 시각 우선(설정·계정), 로그는 합치기.

### 5. Vault 암호화
마스터 비밀번호에서 키를 만들어(Argon2) 항목별 암호화(AES-256-GCM). 암호문만 로컬·Supabase에 저장. 로컬에서는 safeStorage(윈도우 DPAPI)로 한 번 더 감쌈. 앱 시작·일정 시간 미사용 후 마스터 비밀번호 요구. AI는 항목 이름만 보고, 값 입력은 메인 프로세스가 수행.

### 6. ADB + scrcpy
ADB는 구글 공식 폰 제어 통로(USB 디버깅 1회 활성화). scrcpy는 ADB 위에서 화면 전송·터치 전달(지연 35~70ms, 폰 3대 동시). 문자는 ADB 문자함 조회 1순위, 실패 시 화면을 AI가 읽음. ARS 소리는 scrcpy voice-call → 스피커폰+PC 마이크 → 블루투스 순.
경로: `C:\Users\canno\Downloads\pt\platform-tools\adb.exe`, `C:\Users\canno\Downloads\pt\scrcpy-win64-v4.1\scrcpy.exe` (설정에서 변경 가능).

### 7~8. 개발·테스트·배포
TypeScript로 작성, electron-vite로 조립, pnpm으로 부품 설치. Vitest로 함수 검사, Playwright로 앱 흐름 재현. electron-builder로 설치 exe, GitHub Actions가 자동 빌드, electron-updater가 자동 업데이트.
