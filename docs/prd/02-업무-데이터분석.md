# 2차 업무 · 데이터 분석 — 삼바브라우저

작성일: 2026-09-18 · 상태: 확정

## 두 가지 사용 모드

| 모드 | 입력 | 예 | 규모 |
|---|---|---|---|
| **주문 이행 모드** | 삼바 주문페이지(`/samba/orders`)를 브라우저가 열고 화면에서 읽음 | 크림 판매 주문 → 소싱처 대리구매 | 하루 최대 200건, 반복 |
| **자유 지시 모드** | 채팅 한 줄 | "쿠팡에서 콜라 500ml 20캔", "주말 스테이크 레스토랑 예약" | 수시, 1회성 |

두 모드는 같은 엔진(AI + 브라우저 조작 + 폰 인증)을 쓰고, 주문 이행 모드만 "읽기 → 처리 → 기록" 반복 루프가 추가됨.

## 업무 흐름 (주문 이행 1건)

```
삼바 주문페이지에서 미처리 주문 읽기
  → ① 소싱처 후보 사이트들에서 상품 검색, 가격 확인 (KR/JP/CN)
  → ② 최저가 사이트의 계정 2~3개에 각각 접속, 쿠폰·등급 반영 최종가 비교
  → ③ 결제수단 중 최저 비용 선택
  → ④ 결제 (필요 시 문자 인증 / ARS 전화 인증 — 폰 3대 중 온 곳에서 처리)
  → ⑤ 결과를 삼바 주문페이지에 입력 (소싱처·소싱계정·구매금액·소싱처 주문번호·메모)
  → 다음 주문
```

사람 개입 없음이 기본. 예외는 메모 남기고 다음 주문으로.

## 데이터 항목

### A. 삼바 주문페이지에서 읽는 것 (입력)
| 항목 | 삼바 컬럼 | 비고 |
|---|---|---|
| 주문번호 | `order_number` | 처리 단위 키 |
| 상품명 / 이미지 / 옵션 | `product_name`, `product_image`, `product_option` | 옵션에 사이즈·색상 문자열 |
| 모델번호(품번) | 수집상품 조인 `style_code` 등 | 화면에 표시됨 |
| 수량 | `quantity` | |
| 판매가 | `sale_price` | 역마진 판단 기준 |
| 상품 URL | `source_url` | 있으면 탐색 출발점 |
| 판매처 별칭 | `sales_channel_alias` | 예: 마놀(일본) → 국가 힌트 |
| 내부 메모 | `notes` | 이전 실패 사유 확인 |

### B. 삼바 주문페이지에 쓰는 것 (출력)
| 항목 | 삼바 컬럼 | 화면 위치 |
|---|---|---|
| 소싱처 | `source_site` | 인라인 드롭다운 |
| 소싱 계정 | `sourcing_account_id` | 인라인 드롭다운 (**먼저 선택해야 주문번호 칸 활성화**) |
| 구매금액 | `cost` | 인라인 입력 |
| 소싱처 주문번호 | `sourcing_order_number` | 입력 시 삼바 상태 자동 `wait_ship` |
| 메모 | `notes` | 예외 사유, 선택 근거(어느 계정·쿠폰) |

쓰기 방식: 1순위 화면 인라인 편집(사람과 동일). 대안으로 `PUT /api/v1/samba/orders/{id}` API 존재 — 4차에서 선택.

### C. 브라우저 자체 데이터 (자체 DB)
| 항목 | 내용 |
|---|---|
| 사이트 | 이름, URL, 국가, 로그인 방식(id/pw, SMS, MFA), 결제 흐름 메모 |
| 계정 | 사이트, 별칭, 아이디, 브라우저 프로필 ID, 활성 여부 (비밀번호는 OS 자격증명 저장소) |
| 폰 | serial, 별칭, 국가(유심), 연결 방식(USB/WiFi), 마지막 연결 시각 |
| 작업(Job) | 주문번호 또는 자유 지시문, 모드, 상태, 시작/종료 시각, 사람 개입 횟수, 단계별 로그, 결과(선택 사이트·계정·금액) |
| 인증 이벤트 | 시각, 폰, 종류(SMS/ARS), 사이트, 성공 여부 |

### D. 자유 지시 모드 입력
- 지시문 1개 + (선택) 사용 계정/사이트 지정. 결과는 채팅에 요약 + 작업 로그.

## 상태 정의

### 작업(Job) 상태 — 브라우저 내부
`대기 → 가격조사중 → 결제중 → 인증대기 → 완료 | 실패 | 사람확인필요`

| 전이 | 조건 |
|---|---|
| 대기 → 가격조사중 | 큐에서 꺼냄 |
| 가격조사중 → 결제중 | 최저가 사이트·계정·결제수단 확정 |
| 결제중 → 인증대기 | 사이트가 인증 요구 |
| 인증대기 → 결제중 | 인증번호 입력 / ARS 완료 |
| → 완료 | 소싱처 주문번호 확보 + 삼바 기록 완료 |
| → 실패 | 예외 규칙 해당, 메모 기록 |
| → 사람확인필요 | 위험 단어·금액 상한 등 확인 팝업 대기 |

### 삼바 주문 상태와의 연결
- 처리 대상: 삼바 `status = pending`(주문접수) 이고 `sourcing_order_number` 비어 있는 주문.
- 완료 시 소싱처 주문번호 입력 → 삼바가 자동으로 `wait_ship`.
- 브라우저는 삼바 상태를 직접 바꾸지 않음(삼바 규칙에 맡김).

## 예외 규칙 — 전부 "메모 남기고 다음 주문"

| 상황 | 메모 내용 | 작업 상태 |
|---|---|---|
| 모든 소싱처 품절 | `품절: 확인 사이트 목록` | 실패 |
| 역마진(최저가 > 판매가 × 상한 비율, 기본 100%) | `역마진: 최저가 N원 @사이트/계정` | 실패 |
| 인증번호 3분 내 미도착 / ARS 실패 | `인증실패: SMS|ARS, 폰 별칭` | 실패 |
| 로그인 실패·잠금 | `로그인실패: 계정 별칭` + 해당 계정 30분 사용 중지 | 실패 |
| 봇 차단·캡차 | `봇차단: 사이트` + 해당 사이트 프로필 30분 사용 중지 | 실패 |
| 결제 실패 | `결제실패: 수단, 사이트 오류 문구` | 실패 |
| 위험 단어·금액 상한 초과 | 팝업 대기, 응답 없으면 30분 후 메모 | 사람확인필요 |

- 상한 비율·중지 시간은 설정에서 변경.
- 실패 주문은 앱 내 "확인 필요" 목록에 모임. 폰 알림은 이번 범위 밖(추후).

## 항상 사람이 하는 것
- 결제 정보(카드·비밀번호)를 사이트에 미리 저장
- 새 계정 가입, 비밀번호 변경
- 실패 목록 확인 후 재처리 지시
