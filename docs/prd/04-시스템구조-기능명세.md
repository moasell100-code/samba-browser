# 4차 시스템 구조 · 기능 명세 — 삼바브라우저

작성일: 2026-09-18 · 상태: 확정

## 확정 결정 요약

| 결정 | 선택 | 이유 |
|---|---|---|
| 브라우저 엔진 | Electron(Chromium) | 크롬 기반, PC/모바일 전환, 프로필 분리 가능 |
| AI 두뇌 | Claude Agent SDK (Claude Code 구독 로그인 재사용) | API 키·카드 등록 없음. 제한 시 API 키로 전환 |
| AI가 페이지 보는 법 | 구조 스냅샷(요소 번호 목록) | 정확·저렴. 스크린샷은 폰 화면에만 |
| AI 호출량 대책 | **기록·재생** | 첫 실행 AI가 절차 기록 → 이후 AI 없이 재생, 실패 시만 AI |
| 문자 인증 | adb 문자함 조회(1초 폴링) → 실패 시 폰 화면 AI 읽기 | AI 호출 0, 정확 |
| ARS 전화 | 소리: scrcpy voice-call → 스피커폰+PC마이크 → 블루투스 순 시도. 누르기: 폰 화면 키패드 터치 | 윈도우 HFP 미지원 우회 |
| 비밀정보 | **Vault(금고)** — AI는 값 못 봄, 이름으로만 지시 | 개인정보 AI 노출 차단 |
| 비밀정보 수집 | 사람이 로그인·결제할 때 감지해 저장 제안 + 결제 절차 학습 | 크롬은 로그인만, 삼바는 결제까지 |
| 데이터 저장 | SQLite 파일 1개 + Vault는 OS 암호화 | 서버 없음, 백업 = 파일 복사 |
| 삼바 주문페이지 쓰기 | 화면 인라인 편집(사람 방식) | 범용 원칙. 삼바 전용 코드 없음 |

## 모듈 명세

### Browser
- 탭 생성/닫기/전환. 탭마다 `partition`(프로필) 지정 → 쿠키·세션 분리. 프로필 이름 = 계정 별칭.
- PC↔모바일 전환: UA·뷰포트·터치 에뮬레이션. 모바일 창 나란히 옵션.
- 스냅샷: `{url, title, text(≤8,000자), elements[≤150: id, tag, text, type, name, href, isSecret]}`. `isSecret`(비밀번호·카드 칸)은 값 가림.
- 실행기: `navigate, click(id), type(id, text), fill_secret(id, key), select(id, value), scroll, wait, back, new_tab(profile), switch_tab, screenshot`.
- 봇 차단 감지: 캡차·차단 문구 패턴 → 작업 실패 + 해당 프로필 30분 중지.

### Agent
- Claude Agent SDK `query()` 세션. MCP 도구 = Browser 실행기 + Phone 도구 + `done`.
- 시스템 프롬프트: 역할, 안전 규칙(비밀값 직접 입력 금지, 위험 단어 확인), 스냅샷 해석법.
- 호출 상한: 작업당 도구 호출 40회. 초과 → 실패.
- 인증 실패(로그인 없음·한도) 감지 → UI 노란 띠. `ANTHROPIC_API_KEY` 있으면 API 모드.

### Recorder (기록·재생)
- 기록: AI 실행 중 각 단계 `{행동, 대상 선택 기준(텍스트·속성·위치), 입력값 또는 변수명, 전후 URL}` 저장. 레시피에 연결.
- 재생: 같은 레시피 실행 시 저장 절차를 AI 없이 순서대로 실행. 대상 요소 매칭 실패·URL 불일치 → 해당 단계부터 AI 개입 → 성공하면 절차 갱신.
- 변수: 상품명·수량 같은 값은 변수(`{{product_name}}`)로 치환.
- 지표: 재생 성공률, AI 개입 횟수 → 로그 KPI.
- **사람 작업 녹화(이벤트 흐름)**: 녹화 버튼 → 사람이 하는 동안 화면이 아닌 **사건**을 연속 기록(클릭 요소·입력(Vault 항목은 이름만)·스크롤·페이지 이동·탭 전환·대기·완료 신호). 사건마다 보조 스크린샷 1장. 종료 시 AI가 사건 흐름을 레시피(절차+변수)로 정리 → 즉시 재생 가능. Aside의 장면 캡처 방식과 달리 흐름이 끊기지 않음. 결제 흐름 학습도 같은 녹화기 사용.

### Memory (대화 메모리)
- 채팅에서 나온 지시·수정·선호("쿠폰 항상 적용", "배송지는 B창고")를 항목으로 저장. 다음 작업 시스템 프롬프트에 자동 포함.
- 대화 종료 시 반복 가능성 있으면 "자동화로 저장할까요?" 제안 → 레시피 생성.
- 메모리 화면: 항목 목록·검색·삭제·사이트/계정별 범위. Supabase로 동기화.

### Phone
- 장치 관리: `adb devices` 5초 폴링, serial↔별칭 매핑, USB/WiFi(`adb connect`) 모두. 끊김 시 `kill-server && start-server` 1회 자동 복구.
- 화면: scrcpy 4.1을 폰별 프로세스로 실행, 영상 스트림을 폰 패널에 표시. 터치·키 전달.
- SMS: `adb shell content query --uri content://sms/inbox` 1초 폴링, 최근 3분 내 4~8자리 숫자 추출. 실패 시 폰 화면 스크린샷 → AI가 읽기.
- ARS: 통화 수신 감지(`dumpsys telephony.registry`) → 소리 경로(voice-call/마이크/BT) → AI가 안내 듣고 키패드 터치.
- 폰 선택: 담당 폰 고정 없음. 인증 요청 시 3대 모두 감시, 먼저 온 곳 사용. 계정에 담당 폰 지정하면 그 폰 우선.

### Vault
- 항목 유형: 로그인 비밀번호, 결제 비밀번호, 카드(번호·유효기간·CVC·소유자), 여권(번호·만료·영문명), 신분증, 생년월일, 주소, 연락처, 사용자 정의.
- 계정별·전역 두 범위. 화면은 1Password 스타일(목록·검색·그룹·상세).
- 암호화: Electron `safeStorage`(Windows DPAPI) + 선택 마스터 비밀번호. DB엔 암호문만.
- AI 인터페이스: `fill_secret(elementId, key)` — 값은 메인 프로세스가 직접 입력. 스냅샷·스크린샷·로그에 값 없음.
- 잠금: 일정 시간 미사용 시 자동 잠금, 위험 항목(카드·결제비밀번호) 사용 전 확인 팝업(설정).
- **자동 저장 제안(크롬 방식 확장)**: 사람이 직접 로그인·결제할 때 브라우저가 입력 칸을 감지(아이디/비밀번호는 물론 결제비밀번호·카드·OTP 칸까지) → 완료 시 "이 계정에 저장할까요?" 팝업. 크롬·웨일은 로그인만 저장하지만 삼바는 결제 정보까지 계정별로 저장.
- **결제 흐름 학습**: 사람이 결제하는 동안 Recorder가 단계(장바구니 → 결제수단 선택 → 결제비밀번호 입력 → 완료)와 각 칸의 역할을 분석해 사이트별 결제 절차로 저장. 이후 AI·재생은 이 절차 + Vault 항목 이름으로 결제 자동 수행.

### JobRunner
- 작업 유형: 자유 지시(1회) / 레시피 실행(반복, 항목 목록 순회).
- 큐: 사이트당 1개, 전체 3개 동시 실행(설정). 우선순위 = 생성 순.
- 상태: `대기 → 진행중(가격조사/결제/인증대기) → 완료|실패|사람확인필요`.
- 재시도: 일시 오류 2회. 예외 규칙은 2차 문서 표.
- 사람확인필요: 팝업 30분 무응답 → 실패.
- 절전 방지: 작업 실행 중 `powerSaveBlocker` 활성.

### Store (SQLite)
| 테이블 | 주요 컬럼 |
|---|---|
| sites | id, name, url, country, login_type, notes |
| accounts | id, site_id, label, username, profile_partition, phone_id?, paused_until, is_active |
| vault_items | id, account_id?, type, label, ciphertext, updated_at |
| phones | id, serial, label, country, transport, last_seen_at |
| recipes | id, name, prompt, target_sites, account_ids, rules(json), procedure(json) |
| jobs | id, type, recipe_id?, input(json), status, human_touches, started_at, ended_at, result(json), memo |
| job_steps | id, job_id, seq, action, target, ok, error, screenshot_path, at |
| auth_events | id, job_id, phone_id, kind(sms/ars), site_id, ok, at |
| settings | key, value |

### Settings
모델(sonnet/opus), 동시 실행 수, 재시도 횟수, 결제 상한(기본 50만원), 위험 단어 목록, 중지 시간(30분), 역마진 상한 비율, adb/scrcpy 경로, 절전 방지, Vault 자동 잠금 시간.

## 안정성 대비 체크

| 위험 | 대비 |
|---|---|
| AI 한도 초과 | 기록·재생으로 호출 90% 절감, 한도 감지 시 대기·API 키 전환 |
| 봇 차단 | 프로필 분리, 사이트당 동시 1, 차단 감지 → 30분 중지 |
| 계정 잠금 | 로그인 실패 시 즉시 중지, 5회 규칙 |
| 인증 만료·폰 끊김 | 자동 재연결, 인증대기 상태 유지, 3분 타임아웃 |
| 중복 실행 | 같은 입력(주문번호) 작업은 1개만, 큐 삽입 시 검사 |
| 개인정보 유출 | Vault 값은 AI·로그·스크린샷에 없음 |
| 잘못된 결제 | 결제 상한, 위험 단어 확인, Vault 위험 항목 확인 팝업 |
| 데이터 손실 | SQLite 일 1회 자동 백업 파일 |
| PC 절전 | 작업 중 절전 방지 |

## MVP 범위 제안 (6차에서 확정)

1. 브라우저 뼈대 + 탭/프로필 + PC/모바일 전환 + AI 채팅(자유 지시 모드)
2. Vault + 계정 화면
3. 폰 연결 + SMS 자동 입력
4. 기록·재생 + 자동화 레시피 + 작업 큐
5. ARS
