# 1차 문제 정의 — 삼바브라우저

작성일: 2026-09-18 · 상태: 확정

## 한 문장 문제 정의

무재고 위탁판매 1인 운영자가 하루 최대 200건의 주문을 이행할 때, 여러 소싱처·여러 계정·여러 결제수단 중 최저가 조합을 찾아 결제하기까지 **사람이 매 건 1분씩 붙어 있어야 하고, 문자·ARS 인증 때문에 폰 3대를 오가야 한다**.

## 핵심 KPI (1개)

**무인 처리율 80% 이상** — 사람 손을 한 번도 대지 않고 결제까지 끝난 주문 비율.

측정: 주문마다 `사람 개입 횟수` 기록. 개입 0회면 무인 처리. 주간 집계.

## 사용자 정의

- 본인 1명. 코딩 경험 없음. Windows 11 PC 1대, 안드로이드 폰 3대(한국·중국·일본 유심, 담당 유동적).
- 기존 도구(samba-wave, 크롬 확장앱)와 **완전 별개** 제품. 사이트 목록만 참고.

## 자동화 대상 (주문 1건의 흐름)

1. 상품 1개를 여러 소싱처(KR/JP/CN 약 35개 사이트)에서 최저가 탐색
2. 같은 사이트 계정 2~3개 중 쿠폰·등급 적용 후 가장 싸게 살 수 있는 계정 선택
3. 결제수단 중 최저 비용 선택
4. 결제 실행 (문자 인증 / ARS 전화 인증 포함, 하루 약 3회 발생)

## 수동 · 자동 경계

| 자동(AI) | 수동(사람) |
|---|---|
| 최저가 탐색, 계정 선택, 결제수단 선택, 결제 버튼 클릭 | 카드번호·결제 비밀번호 등 결제 정보를 사이트에 미리 저장 |
| 문자 인증번호 읽어 입력 | 새 계정 가입, 비밀번호 변경 |
| ARS 전화 받고 번호 누르기 | 위험 단어·금액 상한 초과 시 확인 |
| 예외 발생 시 사람에게 알림 | 예외 처리 |

## 병목

- 시간(1분/건)보다 **사람이 자리에 붙어 있어야 하는 것**이 진짜 병목. 자리 비우면 전부 멈춤.
- 인증이 걸리면 폰 3대 중 어느 폰에 왔는지 찾아 옮겨 적어야 함.

## 규모 · 위험 (4차 명세에서 반드시 다룰 것)

- 하루 최대 200건 × 계정 2~3개 × 사이트 여러 개 = **AI 호출 수천 회/일**. Claude 구독 한도(5시간 창)로는 부족할 가능성 큼.
  - 대비: 자주 쓰는 사이트는 정해진 절차(어댑터)로 AI 없이 처리하고, AI는 예외·인증·처음 보는 화면에만 사용. 필요 시 API 키 병행.
- 사이트 봇 차단(Akamai 등): 계정별 브라우저 프로필 분리, 호출 간격 조절.
