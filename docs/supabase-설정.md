# Supabase 설정 안내 (비개발자용)

SAMBA Browser 는 여러 PC에서 같은 계정으로 설정·계정·금고(암호문)·북마크를 공유하기 위해
**Supabase** 라는 무료 클라우드 데이터베이스를 씁니다. 이 문서를 위에서부터 그대로 따라 하면 됩니다.

- 걸리는 시간: 처음이면 20~30분 (구글 로그인 설정 6번이 가장 오래 걸립니다)
- 준비물: 인터넷, 이메일 주소, 비밀번호 관리자(크롬 비밀번호 관리자도 괜찮습니다)
- 각 단계 끝에 **"이렇게 보이면 성공"** 문장이 있습니다. 그 화면이 아니면 다음 단계로 넘어가지 마세요.

> ⚠️ 이 문서에 나오는 키 중 **`service_role` 키는 절대 복사하지 마세요.** 그 키 하나면 모든 사용자의
> 데이터를 읽을 수 있습니다. 앱에는 `anon public` 키만 넣습니다.

---

## 1. 가입

1. 브라우저에서 <https://supabase.com> 으로 갑니다.
2. 오른쪽 위 **Start your project** 를 누릅니다.
3. **GitHub 계정으로 계속하기** 또는 **이메일로 가입** 중 편한 쪽을 고릅니다.
   - 이메일로 가입했다면 받은 편지함에서 확인 메일의 링크를 눌러 주세요.

**이렇게 보이면 성공** — 왼쪽에 조직(Organization) 이름이 있고 가운데가 비어 있는
대시보드(Dashboard) 화면이 나옵니다.

---

## 2. 프로젝트 만들기

1. **New project** 버튼을 누릅니다.
2. 항목을 아래처럼 채웁니다.
   - **Name**: `samba-browser`
   - **Database Password**: **길게(20자 이상) 만들어 비밀번호 관리자에 저장**하세요.
     화면의 *Generate a password* 를 눌러 만들면 편합니다.
     이 비밀번호는 데이터베이스에 직접 접속할 때만 쓰는 값이라, **잃어버려도 앱 동작에는 지장이 없습니다.**
   - **Region**: `Northeast Asia (Seoul)` — 한국에서 가장 빠릅니다.
3. **Create new project** 를 누르고 **2~3분** 기다립니다.

**이렇게 보이면 성공** — 프로젝트 이름 옆에 초록색 **Active** 표시가 뜨고,
"Setting up project" 같은 진행 표시가 사라집니다.

---

## 3. 표(테이블) 만들기

1. 왼쪽 메뉴에서 **SQL Editor** 를 누릅니다.
2. **New query** 를 누릅니다.
3. 이 저장소의 **`supabase/schema.sql`** 파일을 메모장 등으로 열어 **내용을 전부 복사**해,
   방금 연 빈 편집기에 **붙여넣습니다**. (일부만 복사하면 안 됩니다. `Ctrl+A` → `Ctrl+C` 를 쓰세요.)
4. 오른쪽 아래 **Run** 을 누릅니다. (단축키 `Ctrl+Enter`)

이 파일은 **몇 번을 다시 실행해도 안전**합니다. 나중에 내용이 갱신되면 같은 방법으로 다시 실행하세요.

**이렇게 보이면 성공** — 편집기 아래 결과 칸에 **`Success. No rows returned`** 가 나옵니다.

---

## 4. 확인

1. 왼쪽 메뉴에서 **Table Editor** 를 누릅니다.
2. 표 목록에 아래 **8개**가 보이는지 확인합니다.

   `profiles` · `workspaces` · `devices` · `settings_sync` ·
   `accounts_sync` · `vault_items_sync` · `bookmarks_sync` · `recipes`

3. 각 표 이름 옆에 **자물쇠 표시(RLS enabled)** 가 있는지 봅니다.
   이 자물쇠가 "내 데이터는 나만 본다"를 보장합니다.
4. **`audit` 이라는 표는 없어야 정상입니다.** SAMBA Browser 는 감사 기록을 클라우드로 올리지 않습니다.
   (유출될 수 있는 정보를 애초에 밖에 두지 않기 위해서입니다.)

**이렇게 보이면 성공** — 8개 표가 모두 보이고, 전부 자물쇠가 켜져 있으며, `audit` 표는 없습니다.

---

## 5. 이메일 로그인 켜기

1. 왼쪽 메뉴 **Authentication** → **Providers** 로 갑니다.
2. 목록에서 **Email** 이 **Enabled** 인지 확인합니다. (보통 기본으로 켜져 있습니다.)
3. 테스트하는 동안에는 **Authentication → Settings** 에서 **"Confirm email"** 을 잠시 꺼 두어도 됩니다.
   메일 확인 없이 바로 가입·로그인을 시험할 수 있습니다.
   **실제로 배포해 쓸 때는 반드시 다시 켜세요.**

**이렇게 보이면 성공** — Providers 목록의 Email 행에 초록색 **Enabled** 배지가 보입니다.

---

## 6. 구글 로그인 켜기

구글 계정으로 로그인하고 싶지 않다면 이 단계는 건너뛰어도 됩니다(이메일 로그인만 쓰면 됩니다).

1. Supabase 에서 **Authentication → Providers → Google** 을 펼칩니다.
   아래에 적힌 **Callback URL (for OAuth)** 을 복사해 둡니다.
   `https://<프로젝트ref>.supabase.co/auth/v1/callback` 형태입니다.
2. 새 탭에서 <https://console.cloud.google.com> (Google Cloud Console) 에 들어갑니다.
3. 프로젝트가 없으면 아무 이름으로 하나 만듭니다.
4. 왼쪽 메뉴 **API 및 서비스 → 사용자 인증 정보(Credentials)** 로 갑니다.
   - 처음이라면 **OAuth 동의 화면**을 먼저 만들라고 합니다. 사용자 유형 **외부(External)** 를 고르고
     앱 이름·지원 이메일만 채워 저장하면 됩니다.
5. **사용자 인증 정보 만들기 → OAuth 클라이언트 ID** 를 누릅니다.
6. **애플리케이션 유형**은 **웹 애플리케이션**을 고릅니다.
7. **승인된 리디렉션 URI** 에 1번에서 복사한 주소를 **그대로** 붙여넣고 **만들기**를 누릅니다.
8. 화면에 나오는 **클라이언트 ID** 와 **클라이언트 보안 비밀번호(Client Secret)** 를 복사합니다.
9. Supabase 의 **Authentication → Providers → Google** 로 돌아와 두 값을 붙여넣고,
   **Enable Sign in with Google** 을 켠 뒤 **Save** 를 누릅니다.

**이렇게 보이면 성공** — Providers 목록의 Google 행에 초록색 **Enabled** 배지가 보입니다.

---

## 7. 앱이 돌아올 주소 등록

구글 로그인은 브라우저에서 이뤄지고, 끝나면 다시 SAMBA Browser 앱으로 돌아와야 합니다.
그 "돌아올 주소"를 미리 허용해 줘야 합니다.

1. **Authentication → URL Configuration** 으로 갑니다.
2. **Redirect URLs** 항목에서 **Add URL** 을 누르고 **`samba://auth`** 를 **추가**합니다.
   (기존에 있던 값은 지우지 말고 **추가**만 하세요.)
3. **Save** 를 누릅니다.

이게 없으면 구글 로그인을 마쳐도 앱으로 돌아오지 못합니다.

**이렇게 보이면 성공** — Redirect URLs 목록에 `samba://auth` 가 한 줄로 보입니다.

---

## 8. 키 복사

1. 왼쪽 아래 **Project Settings**(톱니바퀴) → **API** 로 갑니다.
2. 두 가지를 복사해 메모장에 잠시 붙여 둡니다.
   - **Project URL** — `https://xxxxxxxxxxxx.supabase.co` 형태
   - **anon public** 키 — `eyJ...` 로 시작하는 아주 긴 문자열
3. 같은 화면에 **`service_role`** 이라는 키도 있습니다.
   **이 키는 절대 복사하지 않습니다.** 모든 사용자의 모든 데이터를 읽을 수 있는 키라
   앱에 넣으면 안 됩니다. 실수로 복사했다면 메모장에서 지우세요.

**이렇게 보이면 성공** — 메모장에 `https://` 로 시작하는 주소 한 줄과 `eyJ` 로 시작하는 긴 키 한 줄,
이렇게 딱 두 줄만 있습니다.

---

## 9. `.env` 작성

1. 저장소(SAMBA Browser 소스 폴더) 루트에 있는 **`.env.example`** 파일을 복사해
   같은 폴더에 **`.env`** 라는 이름으로 붙여넣습니다.
   - 윈도우 탐색기에서 이름을 `.env` 로 바꾸기 어렵다면, 메모장으로 새로 만들고
     저장할 때 파일 형식을 **모든 파일**로 바꾼 뒤 이름을 `".env"`(따옴표 포함)로 저장하면 됩니다.
2. `.env` 를 메모장으로 열어 8번에서 복사한 두 값을 채웁니다.

```
SAMBA_SUPABASE_URL=https://xxxxxxxxxxxx.supabase.co
SAMBA_SUPABASE_ANON_KEY=eyJhbGciOi...
```

- `=` 앞뒤에 공백을 넣지 마세요. 값에 따옴표도 붙이지 않습니다.
- `.env` 는 `.gitignore` 에 들어 있어 **깃(GitHub)에 올라가지 않습니다.** 안심하고 채우세요.

**이렇게 보이면 성공** — `.env` 파일이 두 줄 모두 실제 값으로 채워져 있고,
`xxxxxxxxxxxx` 나 `...` 같은 예시 글자가 남아 있지 않습니다.

---

## 10. 동작 확인

1. 터미널에서 `pnpm dev` 를 실행합니다. (이미 실행 중이었다면 껐다가 다시 실행하세요.)
2. 앱에서 **설정 → 계정** 으로 갑니다.
3. 이메일·비밀번호로 **가입** 하거나, 구글 로그인을 누릅니다.

**이렇게 보이면 성공** — 설정 → 계정 화면에 **"동기화: 연결됨"** 이 보입니다. 여기까지가 끝입니다.

---

## 11. 문제 해결

| 증상 | 원인과 해결 |
| --- | --- |
| `Invalid API key` 가 뜬다 | 9번의 URL 또는 anon 키에 오타가 있거나, 값이 잘려서 붙여넣어졌습니다. 8번부터 다시 복사하세요. |
| 구글 로그인 후 아무 일도 일어나지 않는다 | 7번의 Redirect URLs 에 `samba://auth` 가 빠졌습니다. 추가하고 저장한 뒤 다시 시도하세요. |
| 표는 만들어졌는데 앱에서 0행만 보인다 | **정상입니다.** RLS(행 수준 보안)가 다른 계정의 데이터를 가려 주는 것입니다. 내가 넣은 데이터만 보입니다. |
| `.env` 를 고쳤는데 그대로다 | `.env` 는 앱이 시작할 때 한 번만 읽습니다. `pnpm dev` 를 껐다가 다시 실행하세요. |
| 3번에서 빨간 오류 메시지가 난다 | `schema.sql` 의 일부만 복사됐을 가능성이 큽니다. 편집기 내용을 모두 지우고 `Ctrl+A` → `Ctrl+C` 로 전체를 다시 붙여넣으세요. |
| Table Editor 에 표가 하나도 없다 | 3번의 Run 을 누르지 않았거나 다른 프로젝트를 보고 있습니다. 왼쪽 위 프로젝트 이름이 `samba-browser` 인지 확인하세요. |
